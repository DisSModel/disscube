    Land-cover maps: PRODES and classified maps (SITS)¶

    Besides MapBiomas, two adapters bring categorical land-cover maps into a cube. Both follow the same contract as every source: a local GeoTIFF (uint8, nodata 0 by default), its SHA-256 as the source checksum, and a <source>.provenance.json that records the legend used.

    PRODES (disscube.sources.prodes)¶

    PRODES maps deforestation in the Legal Amazon every year. TerraBrasilis distributes one ZIP per edition with a national GeoTIFF and a QGIS style file (.qml) holding its legend.

    from disscube.sources import prodes

files = prodes.download()                     # once; cached in ~/.cache/disscube/prodes
for year in (2008, 2016, 2024):
    prodes.register_prodes_source(cube, f"prodes_{year}", year, bbox, out_dir="raw",
                                  files=files)
    • Download and cache. download() fetches the ZIP to a temporary name and renames it when complete, so an interrupted download never leaves a broken file; later calls reuse it. Set DISSCUBE_CACHE to move the cache. latest_url() asks TerraBrasilis' own download index for the newest edition.
    • Legend from the file. Codes are read from the .qml ("7 d2007", "91 Hidrografia", "100 Vegetação nativa florestal", …), not hard-coded, so a new edition with another encoding is read correctly or fails loudly. Each label is read as one category, by its text (the first rule that fits wins):
    Category Label
    deforested dAAAA (deforestation of the year, e.g. d2007), and rAAAA (residual, e.g. r2015)
    water contains "hidrografia", "hydrograph" or "água"
    clouds contains "nuvem" or "cloud": no data
    non_forest contains "não florest", "nao florest", "non-forest" or "non forest"
    forest contains "florest" or "forest"
    anything else warning in the log; no data

    For the edition prodes_amazonia_legal_2025_v20260408 the legend is: 7–25 d2007…d2025, 50–65 r2010…r2025, 91 Hidrografia, 100 Vegetação nativa florestal, 101 Vegetação nativa não florestal. The legend of an edition is kept in the provenance file. - One map per year, with the codes you choose. For a year Y a pixel is deforested when its label is dAAAA or rAAAA with AAAA ≤ Y (a later one is still forest). The local code of each category is codes; the default is forest 1, deforested 2, and non_forest and water together 3 (non-forest vegetation and water). Categories given the same code are merged, so codes={"water": 4} keeps the hydrography apart:

    prodes.register_prodes_source(cube, "prodes_2024", 2024, bbox, out_dir="raw",
                              files=files, codes={"water": 4})

    In a pipeline file the same is a table of the source:

    [[source]]
id = "prodes_{year}"
type = "prodes"
years = [2024]

[source.codes]            # local code of each category (1 to 255; 0 is no data)
forest     = 1            # vegetação nativa florestal
deforested = 2            # desmatamento até o ano (dAAAA and rAAAA)
non_forest = 3            # vegetação nativa não florestal
water      = 4            # hidrografia; 3 would merge it with the non-forest

    Only these four names are accepted. Clouds and unknown labels are always no data. - Years. The edition distributed today separates deforestation by year from 2007 on (d2007 holds everything cleared up to then). Earlier years raise an error; use MapBiomas for them.

    The provenance records the edition, its URL, the ZIP's SHA-256, the legend and the code of each category.

    Any classified map, e.g. from SITS (disscube.sources.classified)¶

    SITS classifies satellite image time series — including the Brazil Data Cube cubes — into land-cover maps written as GeoTIFFs. register_classified_map() reads such a map (or any categorical GeoTIFF, local or a Cloud-Optimized URL) over an area and registers it with its legend:

    from disscube.sources.classified import register_classified_map

register_classified_map(
    cube, "lulc_sits_2020", "classified/santarem_class_2020.tif", bbox, out_dir="raw",
    time=2020, legend={1: "Forest", 2: "Pasture", 3: "Water"},   # or .qml / .json / .csv
    producer="SITS",
)

    The legend may be a mapping, a QGIS .qml, a .json ({"1": "Forest"} or a list of {"code", "label"}) or a .csv with code,label columns. A map that uses class 0 needs an explicit nodata= so that 0 is not taken as missing.

    To remap codes before registering — e.g. to merge classes — read the map with disscube.sources.read_window, apply disscube.sources.reclassify(window, {old: new}) and register the result with disscube.sources.register_raster.
